# 🚀 Agile Project Management Simulation – Litro Gas Ordering System

A complete **Agile project management simulation** for a Litro Gas Ordering System, developed to demonstrate practical skills in **Agile planning, requirements analysis, backlog management, project documentation, and solution design**.

The project simulates the planning and documentation phase of a mobile and web-based system that enables customers to order gas cylinders online while helping staff manage orders, deliveries, payments, and inventory efficiently.

---

## 📌 Project Overview

The **Litro Gas Ordering System** is designed as a mobile and web-based solution that streamlines the gas ordering and delivery process.

This repository contains the planning and analysis artifacts created in a simulated **Agile project environment using Jira**.

The project focuses on translating business requirements into structured Agile deliverables such as:

* 📋 Epics and User Stories
* 🔄 Agile Product Backlog
* 🗂️ Requirements Documentation
* 🧩 Data Dictionary
* 🎨 UI/UX Wireframes
* 📊 Business and System Rules
* 📑 Project Planning Artifacts

---

## 🎯 Project Objectives

The main objectives of the project were to:

* Apply **Agile project management principles** in a practical scenario
* Identify and document business and user requirements
* Break large features into manageable **epics and user stories**
* Organize and manage a product backlog using **Jira**
* Design initial user interface concepts using **Figma**
* Define system data requirements using a **data dictionary**
* Demonstrate how business requirements can be translated into system features

---

## 🔄 Agile Project Approach

The project followed an Agile-oriented workflow:

```text
Business Requirements
        ↓
Requirement Analysis
        ↓
Epics
        ↓
User Stories
        ↓
Product Backlog
        ↓
Wireframes & Data Design
        ↓
Documentation
        ↓
Agile Project Planning
```

This approach demonstrates how a business idea can be transformed into structured requirements and development-ready project artifacts.

# 📦 Project Artifacts

## 1️⃣ User Stories

Detailed user stories were created for different system users, including **customers and staff**.

### Example

**Customer**

> As a customer, I want to order a gas cylinder online so that I don't need to visit the shop.

**Staff**

> As a staff member, I want to track delivery status so that I can manage customer orders efficiently.

User stories were structured around:

* User role
* Required functionality
* Business value
* System behaviour

---

## 2️⃣ Epics

Major system functionalities were organized into high-level **epics**, which were then broken down into individual user stories.

### Key Epics

| Epic                            | Description                                     |
| ------------------------------- | ----------------------------------------------- |
| 🛒 Online Ordering              | Allows customers to browse and place gas orders |
| 🚚 Delivery Management          | Supports delivery assignment and tracking       |
| 💳 Payment Integration          | Handles online payment-related functionality    |
| 📦 Inventory & Stock Management | Manages cylinder availability and stock         |
| 👤 Customer Management          | Manages customer information and accounts       |
| 📊 Reporting                    | Supports operational and management reporting   |

---

## 3️⃣ 📚 Data Dictionary

A data dictionary was created to document the key data entities, attributes, and relationships required by the system.

### Example Entities

| Entity            | Example Information                                      |
| ----------------- | -------------------------------------------------------- |
| 👤 Customers      | Customer ID, name, contact details                       |
| 🛒 Orders         | Order ID, customer ID, order status, payment information |
| 🛢️ Cylinders     | Cylinder ID, type, stock quantity, availability          |
| 🚚 Delivery Staff | Staff ID, contact details, assigned deliveries/routes    |
| 💳 Payments       | Payment ID, order ID, payment method, payment status     |

The data dictionary helps establish a common understanding of the information required by different parts of the system.
